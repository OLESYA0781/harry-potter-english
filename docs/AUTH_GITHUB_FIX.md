# Исправление входа на GitHub Pages

В логе фактически опубликованной GitHub Pages сборки (run 41610087406,
job 125829508530) VITE_SUPABASE_URL содержал `/rest/v1/` после домена проекта.
Это REST API base, а supabase-js ожидает корень проекта. Клиент добавлял к
этому адресу `/auth/v1` и `/rest/v1`, формируя неверные endpoints. Прежняя
проверка сборки принимала любой HTTPS path; ошибка входа маскировалась общим
сообщением про email/пароль/сеть. Смена пароля не исправляла адрес API.

Теперь общий нормализатор принимает корень и скопированный REST base,
удаляет только известный суффикс `/rest/v1` и лишние пробелы. Неизвестные пути,
userinfo/query/fragment и HTTP отклоняются. GitHub build передаёт в Vite уже
нормализованный URL. Клиент тоже нормализует URL, сохраняя прежний session
storage key для существующей конфигурации Cloudflare. Журналы, ответы, БД,
пользователи и пароли не очищаются/не меняются. Подставленные пробелы по краям
email убираются; пароль не преобразуется.

GitHub Actions дополнительно выполняет read-only GET `/auth/v1/settings`
с публичным apikey. Неверный URL/key или недоступный Auth останавливает
публикацию. Ответы/пароли/токены не запрашиваются и не печатаются. Обычная
Cloudflare build-команда остаётся прежней. Переменные владельцу заново
копировать не требуется: известная ошибка пути исправляется автоматически.

Настоящий invalid_credentials отличается от сетевой ошибки, 429 и ошибки
настроек сервиса в интерфейсе входа.

Проверки: unit-тесты нормализации/классификации; вся cloud-suite запускается
с `TEST_SUPABASE_URL=https://supabase.test/rest/v1/` и проверяет вход,
синхронизацию, конфликты и private photos. Pages build проверен с тем же
суффиксом, Pages production regression — отдельно. Прямое открытие живых
pages.dev/github.io из управляемой среды ограничено proxy (CONNECT 403),
поэтому успешный реальный вход ученицы подтверждается на её устройстве.
