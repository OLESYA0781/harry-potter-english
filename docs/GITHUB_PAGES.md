# Бесплатная тестовая копия GitHub Pages

Репозиторий проверен: **public**. Для публичного репозитория GitHub Pages
доступен на GitHub Free. Видимость и тариф больше не меняем; платных ресурсов
не создаём. [Условия GitHub](https://docs.github.com/en/pages/getting-started-with-github-pages).

Ожидаемый адрес после успешного деплоя:
`https://olesya0781.github.io/harry-potter-english/`.
Это адрес назначения, а не подтверждение уже работающего сайта.
Cloudflare `https://vika-english.pages.dev/` остаётся основным сайтом.

## Что настроено

- Workflow `.github/workflows/pages.yml`: push в main и ручной запуск;
  публикация разрешена только из main. Сборка Node 22, npm ci и dist.
- Build job имеет только contents:read; deploy — pages:write и id-token:write.
- Отдельный build entrypoint требует настройки существующего Supabase и
  отклоняет отсутствующие переменные/привилегированные ключи.
- `PAGES_BASE_PATH` задаёт `/harry-potter-english/` только для Pages;
  обычная сборка Cloudflare по-прежнему использует `/`.
- Пути JSX-картинок используют Vite BASE_URL; CSS url обрабатывает Vite.
  Учебные тексты, дизайн, идентификаторы ответов и логика сохранения не менялись.
- Все ресурсы берутся из репозитория; внешний API остаётся существующим Supabase.
  Pages не обращается к Cloudflare Pages за файлами.

PR №47 с Timeweb не требуется для этого размещения; платный Timeweb не заказывать.

## Однократные действия владельца

1. В репозитории откройте **Settings → Secrets and variables → Actions**.
2. В **Variables** создайте repository variables:

   | Имя | Что скопировать из настроек существующего Cloudflare проекта |
   | --- | --- |
   | VITE_SUPABASE_URL | HTTPS URL существующего Supabase |
   | VITE_SUPABASE_PUBLISHABLE_KEY | Публичный publishable или legacy anon key того же проекта |

   Workflow также поддерживает одноимённые repository secrets, если они уже
   есть. При наличии обоих вариантов приоритет у variables. Значения публичны
   по назначению и попадут в JS-бандл, но их не нужно коммитить или слать в чат.
   Никогда не вводить service_role, sb_secret_, пароль ученицы или API token.
   Новую БД/пользователя/SQL-миграцию не создавать.
3. Откройте **Settings → Pages → Build and deployment → Source: GitHub Actions**.
   Не задавайте Custom domain и не меняйте DNS. При наличии ограничений Actions
   разрешите стандартные actions checkout, setup-node, upload-pages-artifact,
   deploy-pages. Не подключайте платный тариф/платные runners.
4. После принятия PR в main workflow запустится автоматически. Если он уже
   завершился с ошибкой из-за отсутствия переменных, откройте **Actions →
   GitHub Pages test copy → Run workflow → main** после их добавления.
5. Успех должен быть у build и deploy. Фактический опубликованный URL смотрите
   в environment **github-pages** и шаге Deploy test copy. Проверьте SHA main.
   Не считайте наличие артефакта подтверждением публикации.
6. Изменение переменных требует повторной сборки. Следующие push в main будут
   обновлять тестовый сайт. Cloudflare продолжает независимо собирать main.

Если Pages предлагает оплату — остановиться и проверить, что выбран именно
этот публичный репозиторий. Не менять тариф. Следить за бесплатными лимитами
Actions/Pages и не включать платное превышение.

## Сохранение ответов при смене адреса

1. На старом сайте скачать резервную копию через панель прогресса.
2. На каждом устройстве дождаться синхронизации старых локальных изменений;
   разрешить конфликты. Если нужен VPN для этой операции — использовать его
   до проверки нового адреса без VPN.
3. Не очищать localStorage или браузер. Очередь и сессия принадлежат origin и
   не появятся автоматически на другом домене. Если очередь не отправляется,
   сохранить старый браузер/экспорт и отдельно разобрать проблему.
4. На Pages войти существующим аккаунтом и сначала проверить восстановление
   ответов из облака. Автоимпорт/сброс/перенос БД не предусмотрен.

Оба адреса используют рабочие данные одной ученицы: тестовые изменения тоже
попадут в эту БД. Не стирать реальные ответы ради тестов. Для проверки нового
ввода выбрать согласованное пустое поле. Парольный вход не требует изменения
Supabase Site URL; восстановление пароля/OAuth отдельно здесь не настраиваются.

## Проверки

Локальные команды:

```sh
npm run build
npx vitest run --exclude 'work/**' src
npm run test:cloud
# Следующая команда требует публичных переменных существующего Supabase:
node scripts/build-pages.mjs
npx playwright test --config playwright.pages.config.ts
```

Pages-тесты работают с production dist под `/harry-potter-english/`, проверяют
все public-файлы, прямые ссылки, возврат в меню, reload, ошибки браузера,
ресурсы и размеры desktop/tablet portrait/tablet landscape/phone.
Это Chromium, а не реальный iPhone/Safari.

После публикации отдельно проверить **в России с VPN выключенным**:

- Домашний Wi-Fi и мобильная сеть: HTTPS, отсутствие белого экрана.
- Trial, Lesson 0, Lesson 1, Homework, словари, картинки и прослушивание.
- На iPhone Safari и компьютере: прямые ссылки, обновление, видимость полей.
- Вход, восстановление существующих ответов, сохранение нового согласованного
  ответа после reload, появление на втором устройстве.
- Локальная очередь при потере сети и последующая синхронизация без затирания.
- Network: нет запросов к pages.dev или внешнему CDN; Supabase доступен.

Записать дату, сеть, устройство, SHA и результаты без паролей/токенов.
Доступность GitHub Pages и Supabase из России **не гарантируется**.
Если API недоступен, успешная загрузка HTML не означает выполнение задачи;
сохранить локальные изменения и отдельно рассмотреть доступ к тому же API,
не переносить БД и не обходить Auth/RLS.

Публикация пока не подтверждена: управление Pages и проверка Actions variables
через API этой среды возвращали `Forbidden`. Настройки и живой адрес требуют
проверки владельцем. Российская сеть и настоящие iPhone/iPad недоступны в среде.

Результаты подготовки: обе production-сборки прошли (Pages — с фиктивными
публичными настройками, без обращений к рабочей БД); 48 unit-тестов,
18 тестов облачной синхронизации с имитацией API и 5 Pages-тестов прошли.
Все 15 public-файлов проверены побайтово через HTTP с project prefix.
Проверены отказы build entrypoint без ключа, с secret key и legacy service_role.
Локальная среда Node 24.19.0; workflow использует Node 22.
