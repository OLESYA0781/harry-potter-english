# Система уроков Vika English

Обычный адрес `/` открывает кабинет. Текущие 12 учебных глав находятся в модуле `src/lessons/TrialLesson.tsx`, ID `trial`. Адрес `/#/lessons/trial` сразу открывает его на последнем сохранённом этапе. Смена страницы кабинета/урока не изменяет сохранённый номер этапа. Hash-навигация работает на Cloudflare Pages без дополнительных перенаправлений; история Back/Forward браузера поддерживается.

## Реестр и новый модуль

Единственный источник списка уроков — `src/lessons/registry.ts`. Каждая запись содержит уникальный неизменяемый `id`, основное английское название, русский перевод в `subtitle`, дату `addedAt` в ISO-формате, описание, начальное состояние, компонент и функцию `summarize`. Реестр сортируется по убыванию даты; при равных датах — по ID. Дубли ID или некорректные даты приводят к явной ошибке при разработке.

Чтобы добавить настоящий урок:

1. Создайте отдельный модуль в `src/lessons/`. Он получает `LessonProps`: `state`, `setState` и необязательный флаг `canTeach` для преподавательских элементов интерфейса. Задания и иллюстрации находятся в самом модуле/его файлах данных. Используйте функциональные обновления для ответов, зависящих от предыдущего состояния.
2. Задайте отдельное `initialState` формы `LessonState`: `step`, `name`, `answers`, `scores`, `ratings`. В `answers` можно хранить произвольные вложенные черновики и историю попыток. У нового урока может быть собственное число этапов; число учебных глав пробного урока на вложенный прогресс не распространяется.
3. Определите `summarize(state)` → `{ status, percent, detail }`. Статусы: `not-started`, `in-progress`, `completed`; процент 0–100, `detail` — короткое пояснение. Учитывайте реальные выполненные действия, а не переход на последнюю страницу. Для пробного занятия процент отражает проверки основной диагностики, оценки, шесть отличий; неверный проверенный ответ тоже считается выполненным заданием. Процент не является оценкой знаний и не меняет прежний расчёт результатов/PDF.
4. Добавьте определение в массив внутри `sortLessons([...])` в реестре. Новая дата позднее предыдущих поставит модуль наверх. Главное меню, select и верхний список обновятся из реестра автоматически.
5. Компонент сбрасывает только свой `state`: `setState(structuredClone(myInitialState))`. Если сброс удаляет ответы, используйте явное подтверждение в интерфейсе урока, как в Trial Lesson. Не вызывайте `localStorage.clear`, не используйте напрямую глобальный `useProgress` и не пишите в Supabase из компонента урока.
6. Добавьте тесты упражнений, изоляции прогресса и синхронизации; создайте PR от свежего `origin/main`.

Пример подключения существующего компонента нового урока:

```ts
import NewLesson from './NewLesson';
import { newInitialState, summarizeNewLesson } from './newLessonData';

const newLesson: LessonDefinition = {
  id: 'new-lesson',
  title: 'New Lesson',
  subtitle: 'Название нового урока',
  addedAt: '2026-11-01T00:00:00Z',
  description: 'Краткое описание урока.',
  initialState: newInitialState,
  Component: NewLesson,
  summarize: summarizeNewLesson,
};
// В registry.ts: export const lessons = sortLessons([trialLesson, newLesson]);
```

## Совместимость и независимость данных

Рабочие таблицы, старые SQL-миграции, Auth, `useProgress`, `progressStorage` и механизм синхронизации не меняются. Дополнительная SQL-миграция не требуется, и никакой перенос рабочей базы не выполняется.

- Все прежние поля `name`, `step`, `answers:*`, `scores:*`, `ratings:*` навсегда относятся к `trial`. Их ключи, версии и значения не переименовываются. Старые локальные очереди и импорт версий 1/2/3 продолжают обрабатываться прежним кодом.
- Для каждого нового урока создаётся отдельное поле `answers:@vika/lesson/<id>` с `{ version: 1, data: LessonState }`. Сервер уже поддерживает такие ключи ответов и проверяет их версии. Внутри урока доступны только его собственные задания, ответы, результаты, оценки и этап; адаптер находится в `src/lessons/progress.ts`.
- Корневое хранилище остаётся одно: существующий локальный журнал, outbox и RPC синхронизируют все поля, даже когда открыт кабинет или другой урок. Смена маршрута не размонтирует глобальный `useProgress`.
- Правки разных новых уроков имеют разные серверные версии и не мешают друг другу. При одновременной правке **одного нового урока** конфликтуется весь его снимок; обе версии остаются доступны через прежний механизм выбора. Для trial сохраняется прежняя детализация по отдельным полям. Переход на текущую удалённую главу trial возможен при синхронизации, как раньше.
- Restart trial получает состояние без чужих записей, а адаптер возвращает их в корень неизменными. Это сохраняет даже записи пока не подключённых к реестру модулей. Сброс нового урока меняет только его собственное поле.
- Состояние с неизвестной версией/повреждённым форматом не заменяется пустым уроком: показывается ошибка, а сохранённые данные остаются в журнале. Не меняйте формат сохранения, ID или префикс ключей без отдельного плана совместимости.
- Резервная копия и разрешение конфликтов доступны в общей панели облачного сохранения. Поле имени в корне и приветствие на главной странице используют имя пробного занятия; данные задания нового модуля хранятся независимо.

## Проверки

```sh
npm run build
npm test
npm run test:e2e
npm run test:sql
npm run test:cloud
```

Прежние браузерные тесты открывают `/#/lessons/trial`, сохраняя все проверки заданий и PDF; селекторы групп ограничены областью урока, чтобы не захватывать новый раскрывающийся список. Новые проверки кабинета работают с обычным `/`.

`tests/fixtures/platform.html` — изолированная страница Vite dev server с двумя тестовыми модулями. Она нужна для проверки сортировки, независимости, сбросов и работы двух устройств на настоящем PostgreSQL PGlite. Эти модули не добавлены в production-реестр и не входят в обычную сборку `dist`: на рабочем сайте доступен только Trial Lesson / «Пробное занятие».

Production остаётся на https://vika-english.pages.dev, ветка `main`, команда `npm run build`, каталог `dist`. Переменные Supabase и рабочие данные не изменяются. Объединение PR запускает публикацию через существующую интеграцию Cloudflare Pages; отдельного деплоя из Codex нет.

## Видимость преподавательского режима

`src/teacherAccess.ts` задаёт скрытие Teacher mode для конкретного email ученицы. `useTeacherAccess` читает текущую сессию через существующий клиент Supabase и обновляет видимость при изменении входа. Для других аккаунтов и локального урока сохранено прежнее поведение. При запрете Trial Lesson немедленно скрывает кнопку, заметки и ручные оценки преподавателя, а также сбрасывает активный режим; сохранённые оценки не удаляются.

Это настройка интерфейса, а не изменение серверных прав: Auth, RLS, очередь, SQL и доступ к данным остаются прежними. Новым модулям следует учитывать `canTeach` при отображении преподавательских элементов. Отдельного пароля, новой роли или изменений рабочей базы не требуется.

## Совместимость после удаления глав 13–15

Учебный список Trial Lesson включает первые 12 глав. A2/B1 и итоговая страница не отображаются в навигации и не открываются через Next. `Results & PDF` в преподавательской панели открывает отчёт отдельно, без изменения сохранённого этапа урока.

Массив исторических этапов в `data.ts`, номера сохранений и старые ответы A2/B1 сохранены: они нужны для совместимости localStorage, Supabase и PDF. При сохранённом этапе 12/13/14 интерфейс показывает последнюю доступную главу (индекс 11), не переписывая старый номер или ответы. Процент на главной отражает только оставшиеся задания и оценки (52 пункта), без 20 удалённых заданий A2/B1. В отчёте их история показывается, если уже сохранена.

Прежние браузерные сценарии удалённых глав находятся в `tests/archived-browser/`. Текущий `tests/browser/grammar.spec.ts` проверяет отсутствие этих глав и сохранность всех старых ответов при загрузке. Модульные тесты исторической грамматики продолжают выполняться, поскольку её алгоритмы используются в отчётах.
