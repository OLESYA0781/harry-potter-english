# Синхронизация ответов в Supabase

Система уроков совместима с ранее сохранённым прогрессом `main` 9a34242. Содержание, оформление уроков, вычисление результатов не меняются. Без переменных Supabase приложение продолжает локальное сохранение.

## 1. Supabase и учётные записи

1. Создайте Supabase project. В Authentication → Sign In / Providers оставьте вход Email + Password. Отключите **Allow new users to sign up** (публичную регистрацию), anonymous sign-ins и ненужные провайдеры. В интерфейсе приложения регистрации нет.
2. В Authentication → Users → Add user → Create new user создайте одну ученицу с email и сильным паролем. Подтвердите email через Auto Confirm или штатное подтверждение. Передайте пароль ученице по защищённому каналу. Не помещайте его в Git, Cloudflare Pages env или чат.
3. В SQL Editor выполните `supabase/migrations/202610260001_lesson_sync.sql` **один раз**. Альтернатива для проекта с Supabase CLI — обычный процесс `supabase db push` после привязки проекта. Миграция создаёт две таблицы, RLS и RPC; она не создаёт пользователя и не включает его автоматически.
4. Скопируйте UUID созданного пользователя из Authentication → Users и выполните в SQL Editor, заменив UUID:

```sql
insert into public.lesson_students(user_id)
values ('REPLACE_WITH_CREATED_USER_UUID'::uuid)
on conflict do nothing;
```

Добавьте только эту одну запись. Остальные авторизованные аккаунты не получат доступ к прогрессу. Проверка списка:

```sql
select user_id from public.lesson_students;
```

5. В Authentication → URL Configuration укажите Site URL вашего HTTPS-сайта Cloudflare Pages. Redirect URLs добавляйте только для доверенных адресов, если будете использовать подтверждение email или восстановление пароля. Приложение использует парольный вход без redirect и не предоставляет самостоятельный password-reset flow. Восстановление учётной записи выполняет владелец проекта через Supabase.

### Обновление существующего проекта

Перед публикацией новой сборки примените [миграцию ответов](../supabase/migrations/202611260001_answer_sync.sql) в существующем проекте. Для новой базы сначала примените предыдущие миграции по порядку. Проверьте наличие `public.lesson_students`, `public.lesson_progress`, `public.sync_lesson(jsonb,jsonb)` и UUID Вики в таблице учеников. Миграция сохраняет строки, исходные снимки уроков и маркеры импорта. При первом запросе новой версии исходные снимки становятся архивом, а их поля получают отдельные версии. После этого открытая вкладка со старой сборкой должна обновиться для отправки очереди. Сохраните локальную резервную копию перед ручным восстановлением данных.

Чтобы преподаватель видел ответы Вики, привяжите **другой существующий Auth UUID** преподавателя к UUID Вики. Если у преподавателя ещё нет учётной записи, её может добавить администратор в Supabase Authentication. У Вики остаются прежние email, пароль и UUID. Преподаватель входит своим аккаунтом и открывает Teacher’s Mode обычной кнопкой.

```sql
insert into public.lesson_teachers(teacher_id, student_id)
values ('REPLACE_WITH_TEACHER_UUID'::uuid, 'REPLACE_WITH_VIKA_UUID'::uuid);
```

Прежний личный журнал преподавателя сохраняется в его локальном JSON-экспорте. Если браузер уже хранит журнал другой ученицы, для входа используйте отдельный профиль браузера. Фотографии Homework 0 преподаватель может просматривать через закрытый Storage, если он настроен в проекте. Загружает и удаляет файл владелец.

## 2. Переменные Cloudflare Pages

Переменные находятся в настройках проекта Cloudflare Pages → Variables and Secrets для production (и отдельно для доверенных preview-сборок при необходимости). Существующие значения рабочего проекта сохраняйте:

| Переменная | Значение |
| --- | --- |
| `VITE_SUPABASE_URL` | `https://YOUR_PROJECT.supabase.co` из Project URL |
| `VITE_SUPABASE_PUBLISHABLE_KEY` | публичный `sb_publishable_…` из API Keys; допустим старый anon key |

Это переменные **этапа сборки** Vite, они видны в браузере. Не используйте secret key, `service_role`, пароль ученицы, JWT secret или строку подключения к БД. Доступ защищают Auth + серверный allowlist + RLS, а не сокрытие публичного ключа.

Проект публикуется через Cloudflare Pages: корень репозитория, Node 22, команда `npm run build`, результат `dist`, production branch `main`. После изменения переменных нужна новая сборка Pages. Для обновления используйте текущую базу и существующий аккаунт ученицы. Новые уроки используют существующий RPC, Auth, очередь и RLS; подробности в `LESSONS.md`.

Локально: скопируйте `.env.example` в `.env.local`, заполните два публичных значения, затем `npm ci` и `npm run dev`. `.env.local` исключён из Git. Для синхронизации используйте HTTPS или localhost; Web Locks координируют вкладки в современных браузерах. При отсутствии Web Locks остаётся последовательная очередь одной вкладки; для одновременной работы вкладок используйте актуальные Chrome/Safari/Firefox.

## 3. Первый перенос и смена устройства

1. На **прежнем устройстве**, в том же браузере и на том же домене, где ученица занималась, обновите сайт. Смена домена или профиля браузера не переносит localStorage.
2. Откройте «Облачное сохранение», войдите созданной учётной записью и дождитесь окончания синхронизации.
3. До первого запроса с данными урока создаётся неизменяемый снимок исходного локального прогресса. Он остаётся в `hogwarts-cloud-v1.backup` и входит в кнопку «Скачать резервную копию прогресса». Облачные изменения не заменяют этот снимок.
4. Импорт версий localStorage 1, 2, 3 выполняется после входа, с сохранением прежних правил переноса номеров глав. Серверный маркер делает повтор запроса безопасным. Импорт добавляет только **отсутствующие поля**: локальные старые данные без временных меток никогда не перезаписывают существующие облачные значения, включая удалённые ответы. При пропусках показано уведомление; исходные данные остаются в резервной копии.
5. На другом устройстве войдите тем же аккаунтом. Данные подтянутся автоматически. Открытые страницы запрашивают свежие данные по событию Supabase Realtime. Резервная проверка выполняется каждые 5 секунд в открытой вкладке, при возврате фокуса, открытии вкладки и восстановлении сети. Правка ставится в очередь сразу и отправляется после паузы в 600 мс. Кнопка синхронизации позволяет запросить проверку сразу.

`hogwarts-english-v1` сохраняется как совместимая копия состояния. `hogwarts-cloud-v1` хранит владельца, облачные версии, очередь изменений, маркер импорта и резервную копию. Перед асинхронной обработкой каждый ввод синхронно записывается в `hogwarts-outbox:*`: даже немедленная перезагрузка до освобождения блокировки вкладки не теряет изменение. Перед отправкой журнал сохраняет точный пакет и его идентификаторы, чтобы потеря ответа сервера или перезагрузка не привели к повторному применению правки. Статус Saved появляется после ответа сервера. Успешно принятые операции удаляются; ошибки сети и потеря ответа не очищают очередь. Не очищайте данные браузера до синхронизации/экспорта.

Уроки 0–3 и Trial синхронизируют отдельные ответы, черновики, оценки и отметки прогресса. Present Simple также хранит ответы по отдельным идентификаторам, включая задания, перенесённые в Lesson 2. У Homework 0, 1 и 3 отдельные ключи для доступных цифровых полей. В Homework 2 задания выполняются на бумаге, поэтому на странице нет цифровых ответов или отметок для отправки. Порядок слов в одном предложении и связанные поля одной игровой попытки остаются одной записью. Озвучивание и открытые подсказки относятся к текущему интерфейсу.

## 4. Конфликты, отсутствие сети, Restart

Сервер проверяет ожидаемую ревизию каждого поля под блокировкой строки, записывает номер новой ревизии и своё время. Часы устройства не влияют на результат. Правки разных ответов объединяются. При конфликте одного ответа используется последняя подтверждённая облачная ревизия. Отклонённый черновик сохраняется в JSON-резервной копии. Для связанных карточек независимые правки объединяются только при сохранении допустимой раскладки. Очистка сохраняется как пустой ответ или tombstone с собственной ревизией. Запоздалый импорт не меняет существующие серверные значения, включая tombstones. Если старый серверный снимок урока предшествует отдельным ревизиям ответов, отсутствие ответа в нём тоже сохраняется. Пропущенные значения доступны в локальной резервной копии.

**Restart lesson — намеренный сброс**: он синхронизирует пустые значения и tombstones ответов, результатов и оценок, поэтому старый импорт не восстанавливает удалённое. Исходный снимок первого переноса остаётся в резервной копии.

После потери сети уже открытый урок продолжает работать и сохранять изменения. Это не offline PWA: первая загрузка/перезагрузка сайта без сети не гарантируется. Первый вход и обновление истёкшей сессии требуют интернета. SDK Supabase сохраняет и обновляет сессию; выход не удаляет очередь или прогресс. Журнал связан с UUID ученицы. Auth UUID назначенного преподавателя получает доступ к тому же журналу через привязку на сервере.

## 5. Безопасность и проверки

RLS разрешает чтение прогресса самой ученице и её назначенному преподавателю. Прямые INSERT/UPDATE/DELETE запрещены. RPC `sync_lesson_answers` сверяет авторизованный `auth.uid()` со входящей сессией, сам находит UUID ученицы, проверяет ожидаемого владельца и применяет изменения с проверкой ревизий. Миграция добавляет `lesson_progress` в существующую публикацию `supabase_realtime`. Если публикация отсутствует или Realtime недоступен, клиент получает изменения по резервной проверке.

```sh
npm ci
npm run build
npm test
npm run test:sql
npm run test:e2e
npm run test:cloud
```

`test:sql` выполняет настоящую миграцию и проверки доступа на изолированном PostgreSQL PGlite, с минимальными заглушками схемы Auth и ролей. `test:cloud` запускает Chromium, официальный Auth SDK и ту же SQL-функцию на PGlite; сетевые Auth/PostgREST endpoints заменены тестовым сервером маршрутов. Отдельная проверка подаёт событие Realtime через тестовый WebSocket. Производственные ключи и база не используются. `test:e2e` проверяет уроки и экранные результаты без конфигурации Supabase. Для Chromium задайте `PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH`, если он расположен не в `/usr/bin/chromium`.

После настройки рабочей базы дополнительно проверьте реальный вход на двух устройствах, отключение сети, конфликт одного поля, выход/повторный вход и отказ для другого аккаунта. Это проверка интеграции конкретного Supabase project; локальные тесты не подтверждают настройки вашего проекта, SMTP или Cloudflare Pages.

При откате к прежней версии сайта сохраните JSON-резервную копию и не удаляйте облачные таблицы. Предыдущая сборка получит ошибку старого RPC после перехода записи на новый формат. Для продолжения записи снова опубликуйте сборку, использующую `sync_lesson_answers`. Не редактируйте вручную ключи очереди. JSON-экспорт предназначен для сохранности/ручного восстановления владельцем проекта; автоматической загрузки произвольного JSON нет.
