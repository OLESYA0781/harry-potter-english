# Сохранение одной ученицы в Supabase

Система уроков совместима с ранее сохранённым прогрессом `main` 9a34242. Содержание, оформление уроков, вычисление результатов не меняются. Без переменных Supabase приложение продолжает локальное сохранение.

## 1. Supabase и единственная учётная запись

1. Создайте Supabase project. В Authentication → Sign In / Providers оставьте вход Email + Password. Отключите **Allow new users to sign up** (публичную регистрацию), anonymous sign-ins и ненужные провайдеры. В интерфейсе приложения регистрации нет.
2. В Authentication → Users → Add user → Create new user создайте одну ученицу с email и сильным паролем. Подтвердите email через Auto Confirm или штатное подтверждение. Передайте пароль ученице по защищённому каналу. Не помещайте его в Git, Cloudflare Pages env или чат.
3. В SQL Editor выполните `supabase/migrations/202610260001_lesson_sync.sql` **один раз**. Альтернатива для проекта с Supabase CLI — обычный процесс `supabase db push` после привязки проекта. Миграция создаёт две таблицы, RLS и RPC; она не создаёт пользователя и не включает его автоматически.
4. Скопируйте UUID созданного пользователя из Authentication → Users и выполните в SQL Editor, заменив UUID:

```sql
insert into public.lesson_students(user_id)
values ('REPLACE_WITH_CREATED_USER_UUID'::uuid)
on conflict do nothing;
```

Добавьте только эту одну запись. Остальные авторизованные аккаунты не получат доступ к прогрессу. Проверка списка:

```sql
select user_id from public.lesson_students;
```

5. В Authentication → URL Configuration укажите Site URL вашего HTTPS-сайта Cloudflare Pages. Redirect URLs добавляйте только для доверенных адресов, если будете использовать подтверждение email или восстановление пароля. Приложение использует парольный вход без redirect и не предоставляет самостоятельный password-reset flow. Восстановление учётной записи выполняет владелец проекта через Supabase.

## 2. Переменные Cloudflare Pages

Переменные находятся в настройках проекта Cloudflare Pages → Variables and Secrets для production (и отдельно для доверенных preview-сборок при необходимости). Существующие значения рабочего проекта сохраняйте:

| Переменная | Значение |
| --- | --- |
| `VITE_SUPABASE_URL` | `https://YOUR_PROJECT.supabase.co` из Project URL |
| `VITE_SUPABASE_PUBLISHABLE_KEY` | публичный `sb_publishable_…` из API Keys; допустим старый anon key |

Это переменные **этапа сборки** Vite, они видны в браузере. Не используйте secret key, `service_role`, пароль ученицы, JWT secret или строку подключения к БД. Доступ защищают Auth + серверный allowlist + RLS, а не сокрытие публичного ключа.

Проект публикуется через Cloudflare Pages: корень репозитория, Node 22, команда `npm run build`, результат `dist`, production branch `main`. После изменения переменных нужна новая сборка Pages. Текущая база и авторизация уже настроены: для добавления уроков повторно применять старую миграцию и пересоздавать пользователя не требуется. Новые уроки используют существующий RPC, Auth, очередь и RLS; подробности в `LESSONS.md`.

Локально: скопируйте `.env.example` в `.env.local`, заполните два публичных значения, затем `npm ci` и `npm run dev`. `.env.local` исключён из Git. Для синхронизации используйте HTTPS или localhost; Web Locks координируют вкладки в современных браузерах. При отсутствии Web Locks остаётся последовательная очередь одной вкладки; для одновременной работы вкладок используйте актуальные Chrome/Safari/Firefox.

## 3. Первый перенос и смена устройства

1. На **прежнем устройстве**, в том же браузере и на том же домене, где ученица занималась, обновите сайт. Смена домена или профиля браузера не переносит localStorage.
2. Откройте «Облачное сохранение», войдите созданной учётной записью и дождитесь окончания синхронизации.
3. До первого запроса с данными урока создаётся неизменяемый снимок исходного локального прогресса. Он остаётся в `hogwarts-cloud-v1.backup` и входит в кнопку «Скачать резервную копию прогресса». Облачные изменения не заменяют этот снимок.
4. Импорт версий localStorage 1, 2, 3 выполняется после входа, с сохранением прежних правил переноса номеров глав. Серверный маркер делает повтор запроса безопасным. Импорт добавляет только **отсутствующие поля**: локальные старые данные без временных меток никогда не перезаписывают существующие облачные значения, включая удалённые ответы. При пропусках показано уведомление; исходные данные остаются в резервной копии.
5. На другом устройстве войдите тем же аккаунтом. Данные подтянутся автоматически. Открытые страницы проверяют облако каждые 5 секунд, после возврата фокуса/сети и после изменений с задержкой 600 мс. Кнопка синхронизации позволяет запросить проверку сразу.

`hogwarts-english-v1` сохраняется как совместимая копия состояния. `hogwarts-cloud-v1` хранит владельца, облачные версии, очередь изменений, маркер импорта и резервную копию. Перед асинхронной обработкой каждый ввод синхронно записывается в `hogwarts-outbox:*`: даже немедленная перезагрузка до освобождения блокировки вкладки не теряет изменение. Запись очереди подтверждается прежде, чем отправляется в облако. Успешно принятые операции удаляются; ошибки сети и потеря ответа не очищают очередь. Не очищайте данные браузера до синхронизации/экспорта.

Синхронизируется весь `LessonState`: имя, глава, все ответы, черновики, первые/последние проверки, результаты, история и подсказки A2/B1, найденные отличия и оценки преподавателя. Вложенное состояние отдельного grammar challenge передаётся целиком: одновременная работа двух устройств внутри этого же challenge требует разрешения конфликта. Состояния озвучивания, открытой модалки и других временных элементов интерфейса не являются учебным прогрессом.

## 4. Конфликты, отсутствие сети, Restart

Сервер хранит для каждого поля номер версии и идентификатор операции. Запись допускается только при совпадении ожидаемой версии; часы устройств не участвуют. Правки разных полей объединяются. Если два устройства меняют одно поле, локальная правка остаётся в очереди, а облачная версия отдельно сохраняется в кэше. В панели видны обе версии и две явные кнопки выбора. Локальная версия заменит облачную только после такого выбора и повторной проверки версии. При ещё одной конкурентной правке конфликт появится снова.

**Restart lesson — намеренный сброс**: он синхронизирует пустые значения и tombstones ответов, результатов и оценок, поэтому старый импорт не восстанавливает удалённое. Исходный снимок первого переноса остаётся в резервной копии.

После потери сети уже открытый урок продолжает работать и сохранять изменения. Это не offline PWA: первая загрузка/перезагрузка сайта без сети не гарантируется. Первый вход и обновление истёкшей сессии требуют интернета. SDK Supabase сохраняет и обновляет сессию; выход не удаляет очередь или прогресс. Браузер связан с UUID первой ученицы и откажется переносить эту очередь в другой аккаунт.

## 5. Безопасность и проверки

Таблицы защищены RLS. `anon` не может читать или писать. `authenticated` видит только свой прогресс при наличии в `lesson_students`; прямые INSERT/UPDATE/DELETE запрещены. RPC `sync_lesson` имеет фиксированный пустой `search_path`, явно проверяет `auth.uid()` и allowlist, сам выбирает владельца и блокирует строку перед сравнением версий. UUID из тела клиента не используется. Новая регистрация даже при ошибочном включении signup не даёт доступа без серверной записи в allowlist.

```sh
npm ci
npm run build
npm test
npm run test:sql
npm run test:e2e
npm run test:cloud
```

`test:sql` выполняет настоящую миграцию и проверки доступа на изолированном PostgreSQL PGlite, с минимальными заглушками схемы Auth и ролей. `test:cloud` запускает Chromium, официальный Auth SDK и ту же SQL-функцию на PGlite; сетевые Auth/PostgREST endpoints заменены тестовым сервером маршрутов. Производственные ключи и база не используются. `test:e2e` проверяет уроки и экранные результаты без конфигурации Supabase. Для Chromium задайте `PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH`, если он расположен не в `/usr/bin/chromium`.

После настройки рабочей базы дополнительно проверьте реальный вход на двух устройствах, отключение сети, конфликт одного поля, выход/повторный вход и отказ для другого аккаунта. Это проверка интеграции конкретного Supabase project; локальные тесты не подтверждают настройки вашего проекта, SMTP или Cloudflare Pages.

При откате к прежней версии сайта сохраните JSON-резервную копию и не удаляйте облачные таблицы. Старый сайт не знает об облаке; при возвращении новой версии журнал имеет приоритет над совместимой localStorage-копией. Не редактируйте вручную ключи очереди. JSON-экспорт предназначен для сохранности/ручного восстановления владельцем проекта; автоматической загрузки произвольного JSON нет.
