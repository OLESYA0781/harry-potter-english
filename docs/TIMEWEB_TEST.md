# Независимая тестовая копия на Timeweb Cloud

Подготовлено от main `71863e261648faf2f4ec57e9c0da21fc0319e25b`.
Тестовый адрес **ещё не создан**. Аккаунт Timeweb не подключён к этой среде.
Cloudflare Pages, DNS, учебные материалы и база не изменяются.

## Что подготовлено

Используем нативный frontend React/Vite в App Platform, без VPS, Docker,
новой БД, CDN или отдельного хранилища картинок. Все файлы `public/` попадут
в `dist/` вместе с уроками и JavaScript. Маршруты используют `/#/...`.
JS, CSS и изображения загружаются с нового адреса, а API — напрямую из
существующего Supabase. Cloudflare Pages не участвует в обслуживании копии.
Доступность Supabase из конкретной российской сети ещё требует проверки.

Параметры панели сохранены в [settings.json](../ops/timeweb/settings.json).
Это справочник для ручного ввода, а не поддерживаемый провайдером manifest.
Команда [build.mjs](../ops/timeweb/build.mjs) проверяет публичные настройки
Supabase, затем выполняет обычную production-сборку. Она не меняет базу.
Обычная команда Cloudflare `npm run build` остаётся прежней.

## Действия владельца — сначала аккаунт и стоимость

1. Войдите или зарегистрируйтесь на https://timeweb.cloud/.
2. Откройте App Platform → создание frontend-приложения. Не заказывайте ресурс
   и не вводите платёжные данные до согласования стоимости.
3. Посмотрите актуальную тарификацию, регион, оплату запросов/трафика,
   ограничения и возможные дополнительные платежи. Сохраните показанную сумму
   и условия. Бесплатный технический домен не означает бесплатный хостинг.
4. **На этом этапе остановитесь и согласуйте стоимость.** Дальнейшие пункты —
   инструкция на случай отдельного одобрения заказа. Сейчас ресурс не создан.

## Настройки после одобрения стоимости

1. Подключите GitHub с доступом только к `OLESYA0781/harry-potter-english`.
2. Для первого теста выберите ветку `timeweb-test-hosting-config` и последний
   коммит PR. После принятия PR переключите источник на `main`, чтобы не
   оставаться на устаревающей тестовой ветке.
3. Выберите **React frontend**, без SSR; Node.js **22**. Каталог проекта —
   корень репозитория. Не выбирайте HTML/CSS/JS: этот режим не собирает TS/Vite.
4. В расширенных настройках укажите команду сборки:

   ```sh
   npm ci --include=dev && node ops/timeweb/build.mjs
   ```

   Директория сборки: `dist`, точка входа: `index.html`. Отдельный Node-сервер
   и `vite preview` в production не нужны: платформа раздаёт готовые файлы.
5. Добавьте **на этапе сборки** те же значения, что используются в Cloudflare:

   | Переменная | Значение |
   | --- | --- |
   | `VITE_SUPABASE_URL` | HTTPS URL существующего проекта Supabase |
   | `VITE_SUPABASE_PUBLISHABLE_KEY` | Его публичный publishable или legacy anon key |

   Копируйте значения между панелями, не в GitHub/чат. Не используйте
   `service_role`, `sb_secret_`, пароль ученицы или ключ API Timeweb.
   Vite включает публичные значения в JS при сборке; изменение переменных
   требует нового деплоя. Не создавайте нового пользователя или проект БД.
6. Включите автодеплой выбранной ветки из GitHub. Другие ветки не должны
   обновлять этот стенд. Проверьте SHA в логе каждого деплоя.
7. После одобрения заказа запустите деплой. Используйте выданный технический
   HTTPS-домен, проверьте сертификат. Не привязывайте основной домен,
   не меняйте DNS Cloudflare и не подключайте внешний Cloudflare CDN.
8. Запишите фактический адрес и SHA. При ошибке сохраните точный лог;
   отсутствие Node 22 или build variables решайте в настройках/поддержке,
   не отключением проверки Supabase.

Официальные инструкции: [frontend](https://timeweb.cloud/docs/apps/deploying-frontend-apps),
[React](https://timeweb.cloud/docs/apps/deploying-frontend-apps/react),
[автодеплой](https://timeweb.cloud/docs/apps/deployment).

## Защита существующих ответов

Перед первым входом на копию скачайте резервную копию через существующую
панель прогресса на старом сайте. Дождитесь синхронизации локальных изменений
и разрешите конфликты на каждом устройстве. При необходимости для этого
единственного шага используйте доступное соединение со старым сайтом.
Не очищайте localStorage: очереди принадлежат конкретному origin и не
переезжают на новый домен автоматически. Если старые изменения не удалось
отправить, сохраните браузер и экспорт; автоматического импорта JSON здесь нет.

На копии войдите существующим аккаунтом заново. Сначала проверьте восстановление
ответов из облака, затем продолжайте работу. Оба адреса используют одни данные:
тестовые ответы также сохраняются в рабочую БД. Не стирайте реальные ответы
ради теста; проверяйте на согласованном пустом поле. Никаких SQL-миграций,
изменений RLS, Site URL, пользователя или сброса данных этот стенд не требует
при существующем входе по паролю.

## Приёмка после появления адреса

Проверять из России **с выключенным VPN**, отдельно домашний Wi-Fi и мобильную
сеть, iPhone Safari и компьютер. Локальная проверка Chromium не заменяет Safari.

- HTTPS открывается, после обновления нет белого экрана.
- Открываются Trial Lesson, Lesson 0, Lesson 1 и Homework, словари и задания.
- В Network полностью загружаются JS/CSS и все картинки; нет обращений к
  `pages.dev`, внешним шрифтам/CDN. Большая иллюстрация открывается полностью.
- После входа старые ответы восстановились. Новый согласованный ответ остаётся
  после обновления и появляется на другом устройстве; сверить оба адреса.
- При отключении сети ввод сохраняется локально, после восстановления очередь
  отправляется. Не затирать сохранённый ответ с другого устройства.
- На телефоне и iPad нет горизонтальной прокрутки/обрезанных элементов.
- Встроенное прослушивание зависит от голосов ОС/браузера; проверить на iPhone.

Дополнительно с компьютера в той же российской сети:

```sh
python scripts/check_availability.py --url https://ACTUAL-TEST-DOMAIN --label ru-no-vpn --output timeweb-check.json
```

Утилита проверяет загрузку, а не авторизацию и синхронизацию. Для каждого теста
запишите дату, устройство, сеть, URL, SHA, результат и ошибку (без токенов).
Если Supabase недоступен, доступный frontend сам по себе задачу не решает:
остановить приёмку, сохранить локальную очередь и отдельно обсудить решение
доступа к тому же API. Не переносить БД и не обходить Auth/RLS.

До этих проверок результат «работает без VPN» не подтверждён. Основной сайт
остаётся Cloudflare; решение о переносе принимается отдельно. Неудачный
деплой откатывать средствами Timeweb к предыдущему успешному коммиту,
без отката/очистки БД. Отключение тестового ресурса и платежей — отдельно в
панели Timeweb, только по решению владельца.

## Результаты подготовки

- Обычная production-сборка и Timeweb-команда с фиктивными публичными
  настройками прошли локально (Node 24.19.0; Node 22 выбран для панели,
  непосредственно среда провайдера пока не проверена).
- 48 тестов приложения и браузерная проверка локальной загрузки всех уроков
  без внешних CDN прошли. Все 15 файлов `public/` совпали с копиями в `dist/`.
- Проверены отказы сборки без переменных, с secret key и legacy service_role.
- 18 браузерных тестов синхронизации с имитацией API прошли: восстановление,
  очередь offline, конфликты и недоступность Supabase. Рабочая БД не затронута.
- Реальные авторизация/синхронизация на новом домене, российские сети,
  iPhone и инфраструктура Timeweb пока не проверены: адрес отсутствует.
